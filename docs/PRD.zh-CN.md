## 问题陈述

番禺的一位幼儿园老师被要求围绕本土文化做一门主题探究课程——东乡龙舟、醒狮，或者旁边那座祠堂。她带着二十多个孩子，一天的教学排满，还要家访，月计划还等着交。她缺的不是点子，是一份真的跑得动的计划，以及周二早上计划跑不动时能问的人。

有四件事让这件事很难：

**通用助手不稳，而且这个不稳要她买单。** 它答得漂亮，但每次都不一样。同一个问题这轮很好、下轮掉链子，聊到一半前面的上下文就丢了，而她分辨不出一个好答案和一个自信的错答案。她想买的是确定性，拿到的是彩票。

**没有人回答她真正的那个问题。** 请来的专家给全园讲课，不会为她这个班、她这个活动去把脉。她的问题从来不是「主题探究怎么做」，而是「周二这个活动会不会太难」。

**工具在加活，不是在减活。** 实验园的圆桌会上，园长拍板之后请老师提意见，老师说：「最好分析批注都不要让我们写，你们要有个 AI 帮我来分析吧，因为我们的工作量太大了。」任何要她填表、交材料、回流信息的东西，都会被放弃。

**而且记录必须是真的。** 用编出来的儿童发现拼成的课程故事，比没有课程故事更糟：那是拿关于孩子的假话，当成实践证据交上去。

## 解决方案

一个网页陪跑工具：用一小段对话长出整个月的计划，把计划画成一棵她读得懂的树，然后她点哪里就能问哪里、改哪里——同时让记录对「真正发生过什么」保持诚实。

一句话说清形状：**她说清楚要做什么，智能体一次把整个月的计划长出来，之后她点哪里就聊哪里。**

四条性质定义了它：

**确定性优先于灵活性。** 这个产品卖的是绿色小巴，不是红色小巴：站点固定、到得准、慢一点没关系。老师应该能相信第十份计划和第一份一样好。

**成品才是记忆。** 对话是工作面，计划树和记忆库才是留下来的东西。当轮定了却没写进状态的，就等于没发生。上下文不在对话之间传递——每一段对话读同一棵树、写同一棵树。

**证据管的是关于孩子的断言，不管备课。** 一个孩子都还没做过任何事，智能体照样可以把整个月预设出来。它不能做的，是在没有记录证据的情况下断言孩子发现了什么、说了什么、学到了什么。

**壳就是产品边界。** 壳内——学前主题探究课程建设——模型自由发挥。壳外，工具在发出请求之前就拒绝。

## 实现决策

### 数据模型

**每门课一条消息记录，按主体打标签。** 存储仍然是一门课一条记录。每条消息带一个主体：`course`，或者某个节点 id。点开节点渲染的是带这个标签的消息，读起来像一段关于这个节点的私下对话。没有线程这个对象，所以没人聊过的节点就什么都没有——不是一个空会话，也不是任何列表里的一行。

*2026-07-29 已定（原开放问题 7c 关闭）。* 朝湃主张每次点开节点都开一段零上下文的新对话、丢掉之前的历史。最终采用：**存整条，只送最小集。** 这两种主张其实说的是不同的层——他讲的是送进模型的策略，我们讲的是留下来的东西——而下面的分层上下文正好给出他要的效果。选这一边的理由：一条记录保住了全局顺序（能证明老师是先问了 3.2.1、再回头改的周2，各自计时的分开对话做不到），一门课仍然是一个文件，导出与将来的区域汇总都只读一个对象，并且不会为一份十八个节点的蓝图凭空造出十八个空对话。要跟朝湃和阿峰把这套说法走一遍；存储这个决定不依赖他们同意，而上下文策略本来就跟他们要的一致。

**两棵树，只显示一棵。** `course_plan_blueprint` 仍是内容主干，逐节点带出处标记。`course_plan` 是时间投影——月计划 → 周计划 → 活动——它的节点用 `blueprint_refs` 指回蓝图。推导方向永远是蓝图到计划，不反向。面板上只显示一层结构：时间节点，然后一个课程资料分支放不排期的成品。

**根节点是一个阶段，标签写月计划**——一段连续的教学，大约二到五周，不切自然月。更长的课程会长出第二个根。

**日是活动上的一个日期字段，不是树的一层。** 「今天要做什么」是一次筛选。改期是改一个字段，不是换父节点，所以它不会被待复查规则当成结构性改动。

**节点 id 编码层级并且稳定。** 显示编号在客户端确定性生成；模型从不写显示编号。

**两条状态轴，永不合并。** 出处（`confirmed` / `teacher_preset` / `ai_suggestion` / `hypothesis` / `pending_validation`）回答的是「这件事我们有多确定是真的」。`work_status`（`draft` / `adjusting` / `needs_review` / `settled`）回答的是「她的流程走到哪了」。合并会让「正在改」被读成「未经现场验证」。

**四层记忆**——节点、课程、班级、教师——其中班级是一个有名字的新对象，跟现有的年段字段不是一回事。提取默认写课程层；往上扩到班级或教师是老师的主动动作。

### 上下文拼装

**按主体分层，由引擎计算。** 四个带：规则（缓存稳定的前缀）、骨架（每个计划节点一行，只有标题）、焦点（本轮主体节点的正文、祖先摘要、同级标题、它自己的改动理由）、近期（对话窗口，节点轮会收窄）。模型不能自己挑带。

**存下来的历史不等于送出去的历史。** 一次节点对话拿到的是祖先计划加这个节点记录下来的改动理由——不是产生它们的那段长对话。这条保证正是在保留一条记录的同时满足朝湃要求的关键。

**进来用 TSV，出去用 JSON。** TSV 渲染行状的那几个带（计划骨架、记忆、证据索引），同时兼作给分析用的导出附件。模型输出保持 JSON：厂商的 schema 约束没有 TSV 对应物，而且一列错位的 TSV 会**解析成功**但值全错——一列错位把 `hypothesis` 读成 `confirmed`，正是这个产品存在就是为了防住的那种失败。TSV 规则：不留空格子、不放长文、最多约八列、表头带版本标记。

**记忆放在末尾，而且每轮都在。** 班级与课程事实放在末尾的易变段，每一轮都送——绝不按相关性检索，因为一次检索没命中就重现了班级层本来要防的那个失败。增长靠合并与覆盖来收，不靠压缩。

**改动传播只标记，不重算。** 一次修改给下游盖上 `stale_since` 并显示待复查、附上游改了什么；被抵触的上级节点标 `needs_review`。出处既不自动升级也不自动清除。重算下游会悄悄覆盖老师已经确认过的工作。

### 护栏

**三件事，只有三件：** 范围护栏、证据与出处、结构完整性。壳内模型自由发挥。

**范围检查在调用之前跑。** 两个信号——这条消息碰不碰她的课程、它是不是一个纯粹跑题的提问——只有后者出现且前者缺席才拒绝。看的是目的不是关键词：「长沙今天天气怎么样」要挡，「明天下雨的话周二那个户外龙舟活动怎么办」是课程工作。误伤一次损失一个用户，放过一次损失一轮 token。先只记录不拦截，等真实日志跑满一周再开启。

**阶段关卡是拆开，不是废掉。** 顺序检查、以及阶段二和阶段五的证据前置条件都保留——后者就是不可妥协事项 #1 写成关卡的样子。作废的只有 V1.3 的成品前置条件。`node_prerequisite` 整条作废。

**确认必须带引用。** ✓确认按钮去掉之后，模型只能通过引用老师当轮的原话把节点升为 `confirmed`；引不出来的升级会被剥掉并记录。

### 存储与导出

**每一份新状态都可观测、可导出。** `course_plan`、`work_status`、主体标签、四个记忆库、班级列表、范围判定、搜索报告，都要回答同样三个问题：调试抽屉看得到吗、客户端导出带得走吗、管理端导出带得走吗。

**运维日志只存摘要，不存对话。** 范围日志保留六十字摘要——够判断是不是误伤，不至于变成一个装着老师对话的库。

**搜索是我们跑的一步。** GLM/Z.AI 的独立端点、我们拼的查询、只在信息收集阶段触发；其他每一个供应商都会带着原因说明自己不支持。

## 测试决策

**这里一个好的测试，是在能拿到的最高接缝上断言外部行为，并且两个方向都断言。** 只会触发的规则不是规则：每一道护栏都需要一个会踩中的样例，**和**一个必须原样通过的样例。后者通常更重要，因为误伤损失一个用户，误触发只损失一轮。

**接缝优先级。** 先用已有的纯函数——`engine.applyDelta` / `stageGateError`、`harness.validateTurn`、`prompt-builder.buildPromptParts`、`blueprint-util`、`store` 门面。真正新增的只有一个：`plan-tsv.mjs`，纯进纯出，往返一致性写成测试而不是假设。主体标签、上下文带、`plan_delta` 和新增的违规类型，扩展的都是已有覆盖的接缝。

**可照抄的既有做法。** `demo/tests/runtime-harness.test.mjs` 是双向规则样例的范本；`demo/tests/adapter-timeout.test.mjs` 是「一种条件下触发、另一种条件下保持沉默」的范本；`demo/tests/web-search.test.mjs` 把厂商契约钉成形状，改名会响亮地失败；`demo/tests/scope-guard.test.mjs` 是必须放行样例的范本。`tests/integration/harness-line.test.mjs` 仍是开发护栏规则的参考。

**具体承诺。** TSV 转换器的往返一致性，包括会破坏对齐的格子。待复查标记要断言不动出处。确认要断言：没有引用就被剥掉，有引用就保留。证据关卡要断言：没有儿童证据仍然拒绝进阶段二，没有过程证据仍然拒绝进阶段五——就是这个样例，挡住将来某次清理把产品存在的理由删掉。

**污染护栏。** 除非正在实现的 ADR 明确改变了该行为，已有样例必须逐字节通过。因为别的原因需要改动的样例是一个发现，不是一件杂活。

**界面靠渲染验证。** 任何演示端改动都要在真实浏览器里确认过，才能报告完成。

## 不在本期范围

- **区域教研数据仓与面向领导的分析**——第二受众是商业驱动力，但排在第一版之后。它的数据模型不延后：任何涉及儿童观察的汇总，开始采集之前必须先有记录为 ADR 的合规决定。
- **把主题预设网络图当成一件独立成品**——计划树就是主题网络，没有第二张图。资源深度网络图整张删掉。
- **把`核心驱动问题`当成必做内容**——可以触达，但绝不强求；有探究点就够。
- **强制回传**——对老师不强制，同时模型侧的证据关卡一点没松。
- **语音输入**——想要，而且它会把转写长度放大好几倍；等上下文实测出来再说。
- **MiniMax、Kimi 与聚合商的联网搜索**——MiniMax 的对话 API 里根本没有搜索，Kimi 的内建能力没有接。
- **会自己开线程的节点对话**——已在上面定案；根本没有线程这个对象要建。
- **任何状态字段的教师端表单**——这是被交互命题禁掉的，不是排优先级排掉的。
- **AI 绘图、微信小程序封装、多教师协作同一课程、照片音频自动分析、模型微调。**

## 其他说明

**卡在别人身上，不是卡在我们身上。** 活动方案的内容框架（朝湃负责；节点详情视图等它）。六项信息的完整清单（阿峰发到群里的那条消息）。月计划是不是按月上交的文件——如果是，阶段根这个决定要重开。浩然的 Token 与成本实测，每一个上下文决定在它出来之前都只是暂定。

**开发顺序。** 范围护栏已经先落地。接下来是 `course_plan` 加 `plan-tsv.mjs`——纯模块，没有可看的产出，选它是因为它解开了别人都在等的那个实测。然后是记忆分层与班级对象，然后是只读工作台与主体标签，然后是交互画像六维度。

**欠着的度量。** 课程级与节点级各自的每轮提示词 Token、缓存命中率、跑完一门课的成本、**每次切换主体的成本**（每个主体带自己的窄历史，所以一切换就是冷缓存），以及准确率——用 TSV 之后模型对节点编号的引用还准不准。Token 更便宜但指得更不准是一笔坏交易，光看成本数据看不出来。

**一条值得留着的教训。** 这次重写过程中，一条写进 ADR 的判断——`illegal_stage_jump` 什么都没守——被证明是错的，照着它做会把证据关卡删掉。一条以某个已废机制命名的规则，未必属于那个机制。退休一条规则之前，先读它到底在守什么。
